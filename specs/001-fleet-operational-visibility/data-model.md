# Data Model: Fleet Operational Visibility

The field meanings and the OpenTelemetry mapping are in [contracts/run-record.md](./contracts/run-record.md). This file is the stored shape.

## Operational run

One execution of a control-plane action. Table: `operational_runs`.

| Field | Rule |
|-------|------|
| run_id | Unique text. Generated by the recorder. Never reused. |
| action | One of `create`, `teardown`, `health_check`, `repair`, `release`, `backup`, `credential_check`, `model_change`. |
| target | Instance name such as `agent0-6`, or null when the action has no single instance. |
| actor | Operator name or automation name. Required. |
| writer_pid | Process id of the writer. Used to mark a killed run interrupted. |
| outcome | Null while the run is open. Then `succeeded`, `failed`, or `interrupted`. |
| started_at | Time the run was opened. |
| ended_at | Null until the terminal outcome is written. |

A second create or teardown for the same instance inserts a new row. It does not update an earlier row.

State:

1. Open. `outcome` is null. Zero or more stages exist.
2. Succeeded. `ended_at` is set. Required stages for that action are finished.
3. Failed. `ended_at` is set. One stage is the failed stage and carries the cause.
4. Interrupted. `ended_at` is set by the server sweep. The last stage has no finish record.

## Stage record

One OpenTelemetry log record for a run. Table: `operational_stages`. The JSONL line is the same record.

| Field | Rule |
|-------|------|
| run_id | The parent run. Required. |
| stage | Stage name. Required. |
| phase | `start` or `finish`. |
| severity | `INFO` for a normal start or finish, `WARN` for an optional step that the operation continues after, `ERROR` for the stage that fails the run. |
| body | One human-readable sentence. |
| observed_at | Time this record was written. |
| exit_status | Present on a command finish. Absent on a wait. |
| stdout_tail | Redacted, at most 8 KiB. |
| stderr_tail | Redacted, at most 8 KiB. |
| truncated | True when either stream was cut to fit. |
| cause | Last observed result for a wait, or the exit status plus the tails for a command. Absent on a clean finish. |

Validation:

- A `start` record is written and flushed before the stage's work begins.
- A `finish` record is written when the stage ends.
- A failed or interrupted run names the stage that did not finish.
- An optional step that the operation already treats as non-blocking uses `WARN` and does not set the run outcome to failed.

Creation success records these stages as finished: `files_prepared`, `containers_started`, `homeserver_ready`, `matrix_identity_registered`, `agent_zero_credential_derived`, `gateway_installed`, `gateway_health_confirmed`, `retired_bot_stopped`. Certificate issuance is an extra stage. If the step CLI is absent, that stage finishes at `WARN` and the run can still succeed.

Teardown success records `containers_removed` and `directory_removed`, and the terminal record says the instance directory is absent. A failed teardown names the step that stopped and says the instance may still exist.

## Relationship to mutation history

`audit_log` is unchanged. An operational run is not a row in `audit_log`. An `audit_log` row is not rewritten into a stage. The two can mention the same target at the same time. That is the only link.

## Retention

A row and its JSONL line are kept for 30 days from `observed_at` or, for the run row, from `ended_at`. The server deletes older rows and older lines. A missing run identifier reads as not found. It does not return another run.
